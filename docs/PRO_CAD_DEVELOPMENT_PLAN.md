# Varen CAD 专业化开发计划

> 版本：Draft 1.0  
> 制定日期：2026-09-21  
> 适用范围：`varen cad/aicad`、`mechcad-kernel` 以及两者之间的 Agent / WebSocket / REST 契约  
> 当前基线：Varen CAD v0.21.0-beta；产品定位仍是“可验证、可编辑的参数化装配原型”，`production_ready=false`

---

## 1. 计划目标

本计划不是把 Varen CAD 一次性复制成 SolidWorks，而是把产品分阶段推进到：

1. **短期可稳定使用**：用户发消息、配置模型、修改参数、撤销重做、恢复任务时，不出现“无反应、假死、状态丢失、错误不透明”。
2. **中期可工程师辅助设计**：单零件建模具备稳定的参数化特征、草图/面/边引用、局部修改、几何验证和可追溯失败诊断。
3. **中长期可完成机械设计闭环**：装配约束、运动检查、标准件、工程图、尺寸公差和可审计导出形成闭环。
4. **始终保持 AI 的优势**：自然语言理解、草图输入、自动规划、自动修复和过程解释，而不是退化成普通 CAD 的复制品。

### 1.1 目标产品定义

未来第一阶段的专业化目标应定义为：

> **AI 驱动的机械概念设计与工程师复核平台**：能够生成真实 OCC/BRep 参数化模型，允许工程师直接检查、修改、测量、验证和导出工程资料；不通过验证的模型不得被标记为生产就绪。

在没有完成约束求解、全量拓扑追踪、工程图/GD&T 和长期兼容性验证前，不应宣称“可替代专业 CAD”或“可直接投产”。

## 2. 当前基线与主要差距

### 2.1 已有能力

- React + TypeScript + Three.js 三维 IDE。
- FastAPI REST/WebSocket 后端。
- `mechcad-kernel` 基于 OpenCascade / Build123d 的真实几何内核。
- Agent 主路径支持自然语言、多轮对话、工具调用、审批、计划、快照和会话恢复。
- FeaturePlanV3 旧链路仍保留，具备验证、证据、执行报告和历史快照。
- 内核具备公开 op、事务回滚、撤销/重做、拓扑引用、`fillet/chamfer/shell`、孔、阵列、渐开线齿轮、键槽、花键等基础能力。
- 视口已有适配视角、正交/透视、剖切、点选、悬停高亮、透明度、装配干涉显示等基础交互。
- 模型配置中心已有厂商预置、连接诊断、模型列表和参数设置。

### 2.2 当前专业化短板

| 领域 | 当前状态 | 对专业 CAD 的影响 | 优先级 |
|---|---|---|---|
| 任务可靠性 | Agent、WebSocket、Worker、前端状态缺少统一任务状态机 | 用户会把等待、失败、断线误认为卡死 | P0 |
| 参数化编辑 | 有特征图和部分属性修改，但还不是完整的双向参数系统 | 改一个尺寸可能造成下游引用失效 | P0 |
| 几何验证 | 验证能力按特征分布，部分特征仍是 Partial/No | 生成结果不够可证明 | P0 |
| 拓扑引用 | 有几何指纹与 rebind，但还不够稳定 | 插入上游特征后，下游面/边可能断链 | P0 |
| 草图约束 | 主要依赖参数化 op，没有完整二维约束求解器 | 无法像专业 CAD 一样拖动、约束、自动求解 | P1 |
| 视口编辑 | 主要是只读查看、点选和面板编辑 | AI 与人工修改仍然割裂 | P1 |
| 装配约束 | 目前更偏向位姿和静态干涉 | 无法表达同轴、共面、齿轮啮合、运动自由度 | P1 |
| 工程图 | 暂无完整 2D 投影、剖视、标注、图框 | 无法形成制造交付物 | P1 |
| GD&T/公差 | 目前只有名义尺寸和部分设计审查 | 不能支持正式工艺和检验语义 | P2 |
| 标准件库 | 传动件已有突破，但紧固件、轴承、密封件等不完整 | 真实机械设计效率低 | P1 |
| 大装配性能 | 几何加载、渲染、干涉检查仍需压力测试 | 复杂装配体验容易下降 | P0 |
| 版本兼容 | 还需要稳定的模型格式、迁移、回放和诊断包策略 | 无法长期维护用户项目 | P0 |

## 3. 总体路线图

建议以 **24 周为一个专业化主周期**，采用“先可靠、再可编辑、再装配、再工程交付”的顺序。

| 阶段 | 时间 | 目标 | 主要交付物 |
|---|---:|---|---|
| Phase 0 | 第 1–2 周 | 稳定任务体验，消除“无反应/假死” | 任务状态机、错误码、断线恢复、取消/重试、诊断日志 |
| Phase 1 | 第 3–6 周 | 单零件参数化建模达到可复核 | 特征契约、局部失败保留、验证补全、引用稳定性 |
| Phase 2 | 第 7–10 周 | AI 与人工编辑闭环 | 测量工具、面/边/特征联动、参数编辑、视口 Gizmo 雏形 |
| Phase 3 | 第 11–16 周 | 装配约束与运动检查 | Mate 模型、DOF、静态/动态干涉、装配诊断 |
| Phase 4 | 第 17–21 周 | 工程图与基础制造资料 | 投影视图、剖视、尺寸、基础公差、PDF/DXF |
| Phase 5 | 第 22–24 周 | 工业化发布与设计伙伴验证 | 性能基线、兼容迁移、回放测试、Beta 2/RC |

并行原则：

- Phase 0 必须先完成，后续所有功能都建立在可观测、可恢复的任务系统上。
- Phase 1 的几何契约和稳定 ID 是 Phase 2–4 的共同依赖，不能绕过。
- 2D 工程图不应过早做 UI，先冻结 BRep、特征、装配和公差数据模型。
- AI 自动化必须通过相同的公开 API 和验证门，不允许为 Demo 增加旁路逻辑。

## 4. Phase 0：可靠性与真实用户体验（第 1–2 周，P0）

### 4.1 目标

用户任何一次发送都必须得到明确结果：

- 已排队、执行中、等待用户、已完成、失败、已取消、已恢复，不能出现空白状态。
- 后端失败必须在聊天、过程面板和诊断信息中一致呈现。
- 浏览器刷新、WebSocket 断开、后端重启后，用户能够恢复会话和最新快照。

### 4.2 开发任务

#### A. 统一 Agent 任务状态机

新增统一状态：

```text
idle
queued
starting
planning
waiting_user
executing
validating
committing
completed
failed
cancelled
recovering
```

每个任务都必须具有：

- `job_id`
- `project_id`
- `run_id`
- `session_id`
- `created_at / started_at / finished_at`
- `state`
- `last_event_id`
- `error_code / error_message`
- `cancelable / resumable`

#### B. WebSocket 事件契约

统一事件结构，禁止不同模块自行拼接 payload：

```json
{
  "event_id": "evt_...",
  "job_id": "job_...",
  "run_id": "run_...",
  "type": "agent_progress",
  "state": "executing",
  "message": "正在执行第 4/12 步",
  "payload": {},
  "timestamp": "..."
}
```

至少覆盖：

- `agent_started`
- `agent_queued`
- `agent_state_changed`
- `agent_text_delta`
- `agent_tool_started`
- `agent_tool_finished`
- `agent_snapshot`
- `approval_required`
- `question_required`
- `agent_done`
- `agent_failed`
- `agent_cancelled`
- `agent_recovered`

#### C. 前端不可见失败清零

- 发送后立即创建带状态的助手消息，不等待第一个 token。
- 超过 3 秒没有事件，显示“仍在连接模型/等待 Worker”，不是空白。
- 超过可配置阈值显示“继续等待 / 取消任务 / 查看诊断”。
- 所有 `agent_done(ok=false)`、REST 4xx/5xx、WebSocket close、JSON 解析错误都进入聊天错误气泡。
- 设置保存采用明确的 `保存并关闭`、`取消修改`，自动保存只能作为保险，不能让用户不清楚保存结果。

#### D. 取消、重试、恢复

- 取消必须唤醒模型调用、审批等待和 Worker 等待。
- “重试”必须携带原始 `job_id` 和错误上下文，避免重复提交两次任务。
- 刷新页面后通过 `GET /agent/session` 与 `GET /runs/{run_id}` 恢复 UI。
- WebSocket 重连后使用 `last_event_id` 补发，而不是从头重复执行。

#### E. 诊断能力

增加本地诊断包：

- 项目 ID、版本、操作系统、模型配置摘要（API Key 脱敏）。
- 最近 1000 条事件。
- Agent 错误、Worker 错误、内核错误、浏览器错误。
- 当前 FeatureGraph、最近快照、执行报告摘要。
- 不保存原始 API Key，不默认上传用户模型文件。

### 4.3 验收标准

- 发送后 300ms 内出现任务状态反馈。
- 未配置模型、端点错误、超时、模型返回非法工具调用时，用户能在聊天区域看到可理解错误。
- 断开 WebSocket 后 5 秒内自动重连；恢复后消息顺序不重复、不丢失。
- 连续执行 100 次“生成/取消/重试/刷新”流程无项目状态损坏。
- 失败任务不得生成伪成功快照，`production_ready` 仍为 false。

## 5. Phase 1：单零件参数化与几何可信度（第 3–6 周，P0）

### 5.1 目标

把单零件从“AI 调 op 生成形状”提升到“可修改、可追踪、可验证的特征模型”。

### 5.2 特征能力分级

#### 第一优先级：必须达到完整语义

- `box_base`
- `cylinder_base`
- `hollow_cylinder`
- `through_hole`
- `blind_hole`
- `counterbore_hole`
- `rectangular_slot`
- `rectangular_pocket`
- `boss_cylinder`
- `fillet`
- `chamfer`
- `linear_pattern`
- `circular_pattern`

每种特征必须拥有：

- 参数 schema。
- 输入引用 schema。
- 前置条件与几何范围校验。
- Worker 执行映射。
- 输出实体/面/边演化记录。
- 几何证据和语义验证。
- 可编辑字段列表。
- 失败原因与可修复建议。

#### 第二优先级：传动和制造特征

- 螺纹孔 / 外螺纹。
- 键槽、花键、轴肩、退刀槽。
- 拔模、薄壁、加强筋。
- 旋转、放样、扫掠的稳定输入引用。

### 5.3 几何契约

统一定义三层结果：

1. **几何存在**：是否生成合法 BRep、实体数、体积、包围盒。
2. **语义符合**：孔是不是孔、倒角半径是否正确、槽是否贯通、阵列数量是否正确。
3. **工程可接受**：最小壁厚、干涉、可加工性、尺寸范围、材料和工艺假设。

禁止只依赖：

- LLM 的文字说明。
- 体积变化单一指标。
- STL 网格视觉判断。
- “Worker 没有抛异常”作为成功依据。

### 5.4 拓扑引用与特征历史

- 特征 ID 与几何实体引用分离：`feature_id` 不得等同于 OCC face/edge index。
- 每次重建记录 `created / modified / split / merged / deleted / rebound`。
- 引用失败时返回候选列表和几何摘要，禁止静默绑定到“看起来最像”的面。
- 引入引用置信度：`exact / rebound / ambiguous / invalid`。
- 对 `ambiguous` 强制要求用户或 Agent 确认。
- 增加上游特征插入、参数修改、删除、重排的回放测试。

### 5.5 局部失败与模型恢复

专业 CAD 不应因为最后一个特征失败而隐藏前面所有结果。因此：

- 每个特征提交独立 checkpoint。
- 失败特征保留在特征树并标红。
- 视口展示最后一个有效版本。
- 提供“编辑失败特征”“抑制特征”“回滚到此处”“从此处继续”。
- AI 自动修复必须显示修复前后参数差异并允许撤销。

### 5.6 验收标准

- 12 类核心特征全部具备正向、负向、边界和回放测试。
- 插入上游特征后，下游引用保持 `exact` 或可审计 `rebound`；不得静默错面。
- 任意特征失败时，前序有效几何仍可查看和导出诊断快照。
- 同一 FeatureGraph 在相同内核版本和参数下重复执行结果指纹一致。
- 关键特征语义验证通过率达到 95% 以上，未知结果不能自动标记 PASS。

## 6. Phase 2：AI 与人工编辑闭环（第 7–10 周，P0/P1）

### 6.1 目标

让用户不必每次都回到聊天框或属性面板，能够在视口和特征树中直接理解、测量、修改模型；AI 修改和手工修改共用同一套参数化历史。

### 6.2 视口基础工具

第一批必须实现：

- 点到点距离。
- 点到面距离。
- 面到面距离。
- 圆柱直径/半径。
- 轴线夹角。
- 包围盒尺寸。
- 最小壁厚检查。
- 测量结果锁定、复制、添加到对话上下文。

测量结果必须带：

- 选中的实体引用。
- 坐标系。
- 单位。
- 精度和容差。
- 是否来自真实 BRep 还是网格近似。

### 6.3 参数化直接编辑

分三步做，不建议一开始做万能拖拽：

1. **安全编辑**：点击特征树字段，修改尺寸，预览 diff，确认重建。
2. **视口锚点编辑**：拖拽孔中心、拉伸方向、旋转轴长度等有限参数。
3. **通用 Gizmo**：平移、旋转、缩放只作用于允许编辑的特征，不直接破坏实体历史。

所有直接编辑必须生成标准命令：

```text
select feature -> preview change -> validate -> commit snapshot
```

不能由前端直接改 Three.js 网格后假装修改了 CAD 模型。

### 6.4 特征树专业化

- 树节点显示状态：有效、抑制、失败、待确认、过期引用。
- 节点显示输入和输出引用。
- 支持搜索、过滤、重命名、抑制、删除、回滚。
- 选择树节点时高亮对应几何。
- 选择面/边时定位所属特征。
- 右键菜单统一操作，不能出现同一动作多个实现。

### 6.5 验收标准

- 用户可以仅通过“选择特征 → 改参数 → 保存并重建”完成 80% 的常见单零件修改。
- 测量结果误差与 OCC 查询结果一致；网格近似结果必须明确标注。
- 视口选择、特征树选择、聊天引用三者能互相跳转。
- 任何人工修改都可撤销、重做，并出现在过程记录中。

## 7. Phase 3：装配约束、自由度与运动检查（第 11–16 周，P1）

### 7.1 目标

从“按绝对位姿摆放零件”升级到“按工程约束定义装配关系”。

### 7.2 装配数据模型

新增独立于零件 FeatureGraph 的 `AssemblyGraph`：

```json
{
  "components": [
    {"id": "comp_001", "part_id": "part_001", "fixed": true}
  ],
  "mates": [
    {
      "id": "mate_001",
      "type": "concentric",
      "a": {"component": "comp_001", "ref": "axis_12"},
      "b": {"component": "comp_002", "ref": "axis_03"},
      "offset_mm": 0,
      "flip": false
    }
  ]
}
```

第一批 Mate：

- 固定 / Ground。
- 同轴 / Concentric。
- 共面 / Coincident。
- 平行 / Parallel。
- 垂直 / Perpendicular。
- 距离 / Distance。
- 角度 / Angle。
- 相切 / Tangent。

第二批：

- 齿轮啮合。
- 皮带/链条关系。
- 旋转副。
- 滑动副。
- 螺旋副。

### 7.3 求解与诊断

- 维护每个组件的 6 DoF 状态。
- 报告欠约束、过约束、冲突约束和孤立组件。
- 添加 Mate 前预览求解结果。
- 失败时保留原装配，不提交半成品。
- 约束来源可追踪：用户创建、AI 创建、模板创建。
- AI 添加约束前必须显示“将固定哪些自由度”。

### 7.4 运动和干涉

阶段一只做确定性静态检查：

- 指定姿态下的碰撞矩阵。
- 接触面、穿透体积、最小间隙。
- 齿轮中心距、模数、齿数、旋转方向检查。

阶段二做运动扫描：

- 对旋转副按角度采样。
- 对滑动副按位移采样。
- 记录首次碰撞姿态和最小间隙。
- 生成干涉报告和可视化标记。

### 7.5 验收标准

- 三类典型装配：轴承-轴、齿轮-轴、箱体-盖板能用 Mate 重建。
- 约束冲突可定位到具体 Mate。
- 装配移动后零件姿态由约束重新求解，不依赖手工同步绝对坐标。
- 运动扫描至少覆盖减速器、铰链、滑块三类案例。

## 8. Phase 4：工程图、尺寸和基础公差（第 17–21 周，P1/P2）

### 8.1 目标

把三维模型转化为工程师可以复核、打印和继续编辑的二维资料。

### 8.2 数据层先行

工程图不能从截图开始做，应先建立：

- `DrawingDocument`
- `Sheet`
- `View`
- `SectionView`
- `DetailView`
- `Dimension`
- `Annotation`
- `Datum`
- `Tolerance`
- `TitleBlock`

工程图对象必须引用稳定的特征/面/边标识，而不是只保存屏幕像素坐标。

### 8.3 第一阶段工程图能力

- 主视、俯视、左视、等轴测视图。
- 自动投影和比例设置。
- 隐藏线、切线、特征边显示。
- 全剖视和简单局部剖视。
- 线性、直径、半径、角度、弧长尺寸。
- 基础标题栏、单位、比例、材料、版本号。
- PDF 和 SVG 输出。

### 8.4 第二阶段公差和制造标注

- 尺寸上下偏差。
- 配合标注，如孔轴配合。
- 基准 A/B/C。
- 位置度、平面度、垂直度、同轴度、圆跳动等基础 GD&T。
- 表面粗糙度。
- 焊接、去毛刺、热处理等制造注释。

### 8.5 验收标准

- 典型法兰、轴、箱体和装配体可自动生成四视图。
- 视图可重新定位、缩放、隐藏线切换，不依赖重新生成模型。
- 输出 PDF 与屏幕预览几何一致。
- 图纸上的尺寸引用可以反向定位到三维特征。
- 未定义公差不自动补成“看似专业”的值，必须显示未指定状态。

## 9. Phase 5：标准件、性能和发布工业化（第 22–24 周及持续迭代）

### 9.1 标准件库

优先顺序：

1. ISO/GB 螺栓、螺母、垫圈。
2. 深沟球轴承、圆锥滚子轴承、角接触轴承。
3. 平键、挡圈、销、O 型圈。
4. 密封、联轴器、皮带轮、链轮。
5. 材料库和表面处理库。

每个标准件必须包含：

- 标准号和版本。
- 参数范围。
- 材料与质量属性。
- 可替换族关系。
- 供应商/用户自定义字段。
- 2D 图纸和 3D BRep/网格。
- 单位与舍入规则。

### 9.2 大装配性能

目标不是单纯提高 FPS，而是维持交互可用性：

- 视口首帧时间。
- 模型加载进度。
- 零件分层加载。
- LOD 和边线预算。
- 只对可见/选中/干涉相关零件做精细检查。
- 后台执行碰撞矩阵，避免阻塞 UI。
- 缓存按几何指纹和材质版本命中。

建议建立基准装配：

| 基准 | 零件数 | 目标 |
|---|---:|---|
| 小型单零件 | 1 | 首次显示 < 1 s |
| 中型装配 | 20 | 首次显示 < 3 s，交互保持流畅 |
| 复杂装配 | 100 | 可渐进加载，UI 不阻塞 |
| 压力装配 | 300+ | 明确降级策略，不假装实时 |

### 9.3 项目兼容与发布

- 项目文件带 schema 版本、内核版本、提示词版本、模型配置版本。
- 启动时自动迁移旧 schema，迁移前创建备份。
- 旧版本项目只读打开时给出兼容提示。
- 每次发布运行固定案例回放。
- 记录几何指纹变化，避免内核升级后静默改变模型。
- 发行包包含诊断工具、日志清理工具和模型配置导入导出。

## 10. AI Agent 专项计划

### 10.1 Agent 不能直接决定的内容

以下内容必须由程序验证或请求用户确认：

- 关键尺寸缺失时的最终数值。
- 面/边引用发生 ambiguous rebind 时的选择。
- 破坏性操作、删除特征、替换零件。
- 生产材料、公差、热处理等工程假设。
- 干涉豁免和齿轮啮合区例外。
- 图纸上的未指定公差。

### 10.2 Agent 工具协议要求

每个工具必须声明：

- 输入 JSON Schema。
- 是否只读。
- 是否破坏性。
- 是否可撤销。
- 前置条件。
- 成功结果结构。
- 可恢复错误结构。
- 是否会改变 FeatureGraph / AssemblyGraph / DrawingDocument。

工具返回不能只返回自然语言，应同时返回机器可读信息：

```json
{
  "ok": false,
  "error_code": "TOPOLOGY_REFERENCE_AMBIGUOUS",
  "recoverable": true,
  "suggestions": [
    {"action": "re_select", "candidates": ["F12", "F18"]}
  ],
  "state_changed": false
}
```

### 10.3 Prompt 与模型评估

建立固定任务集，而不是只看 Demo：

- 10 个单零件生成。
- 10 个尺寸修改。
- 10 个失败修复。
- 10 个装配定位。
- 10 个图纸/标注任务。
- 10 个含图片草图任务。

指标：

- 首轮成功率。
- 无人工干预成功率。
- 平均工具步数。
- 错误恢复成功率。
- 几何契约通过率。
- 用户确认次数。
- 错误后状态损坏率。
- 平均完成时间。

## 11. 测试和质量门禁

### 11.1 单元测试

- Schema 和错误码。
- 特征 normalizer / validator。
- 引用解析和 rebind。
- 几何测量与语义验证。
- 装配 Mate 求解。
- 图纸投影和尺寸对象。
- 前端状态机、聊天、设置、视口选择。

### 11.2 集成测试

- REST 创建任务 → WebSocket 流 → Worker → 快照提交。
- 模型未配置、模型超时、断线、刷新、取消、重试。
- Agent 产生非法工具调用时的回滚。
- 内核重启后恢复任务。
- 特征修改后导出 STEP 与执行报告一致。

### 11.3 回放测试

每次发布固定回放：

1. 法兰 + 通孔 + 阵列。
2. 套筒 + 槽 + 倒角。
3. 轴 + 键槽 + 轴承。
4. 齿轮 + 轴 + 箱体。
5. 多零件变速器。
6. 失败特征修复。
7. 断线恢复和审批恢复。

### 11.4 质量门禁

任何版本进入 Beta/RC 前必须满足：

- P0 缺陷为 0。
- 任务失败不产生伪成功快照。
- 所有新公开 op 有 schema、执行、验证、回滚和测试。
- 关键回放案例几何指纹变化必须有解释。
- 不允许将 `UNKNOWN` 验证结果升级为 `PASS`。
- 不允许在前端绕过后端契约直接修改 CAD 状态。
- API Key、项目文件和用户图片不得进入普通日志。

## 12. 推荐团队拆分与依赖关系

如果是小团队或单人开发，不应同时铺开所有方向，建议按以下顺序投入：

### 角色 A：内核/几何

负责：特征契约、拓扑引用、验证、装配约束、图纸投影。

### 角色 B：Agent/后端

负责：任务状态机、事件协议、工具 schema、会话恢复、错误码、回放框架。

### 角色 C：前端/交互

负责：聊天状态、特征树、测量、视口编辑、装配约束交互、图纸界面。

### 角色 D：测试/工程化

负责：基准案例、回归、性能、诊断包、发布和设计伙伴反馈。

若只有 1 人开发，推荐采用：

```text
可靠性 → 核心特征验证 → 测量/特征编辑 → 标准件 → 装配 Mate → 工程图
```

不要在单人模式下同时开发“约束求解器、工程图、标准件商城和复杂 AI 自动修复”。

## 13. 每两周评审机制

每个迭代结束必须回答五个问题：

1. 用户能否明确知道系统当前在做什么？
2. 失败时能否恢复，而不是只能刷新或重建项目？
3. 生成的几何是否有程序证据，而不是只看图？
4. 人工修改是否真正进入参数化历史？
5. 新功能是否增加了旁路、重复状态或不可追踪的隐式逻辑？

评审材料必须包括：

- 本迭代新增功能。
- P0/P1 问题关闭情况。
- 典型任务录屏或事件回放。
- 几何验证报告。
- 性能数据。
- 已知限制和下一迭代不做事项。

## 16. 最重要的取舍

### 现在不要优先做

- 更多炫目的渲染效果。
- 只增加模型厂商数量。
- 没有验证契约的新建模 op。
- 只对 Demo 有效的复杂装配模板。
- 没有稳定 ID 的“万能拖拽编辑”。
- 在没有图纸数据模型前直接做漂亮图纸 UI。

### 现在必须优先做

- 任何任务都有明确状态和错误反馈。
- 失败可恢复，且不污染项目状态。
- 特征修改可追踪、可撤销、可重放。
- 几何结果有语义验证，不只看体积和截图。
- 用户可以测量、选择、定位和解释模型。
- AI 与手工操作共用一条正式的参数化内核路径。

## 17. 成功判断

当以下条件同时满足时，Varen CAD 可以从“AI CAD 原型”进入“工程师复核版”：

- 设计伙伴连续使用一周，不再出现“点击发送没有反馈”的问题。
- 典型单零件任务成功率和可恢复率稳定，失败能够定位到具体特征。
- 工程师可以不依赖重新对话完成常见尺寸修改、测量和撤销。
- 装配中的位置关系以约束表达，而不是只保存绝对坐标。
- 至少能生成可复核的基础工程图和尺寸资料。
- 所有导出物都能追溯到项目、运行、特征、验证和内核版本。
- 产品仍明确标注：未经工程师审核，不得直接用于生产。
