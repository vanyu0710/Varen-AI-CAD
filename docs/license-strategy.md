# Varen CAD 许可证策略（决策备忘录）

**日期**：2026-09-16 · **状态**：待创始人最终确认（重大决定，建议咨询开源/软件商业授权律师）

## 背景事实

- 内核 `mechcad-kernel`：已声明 AGPL-3.0-or-later，版权由本团队持有。
- 主仓 `aicad`：此前无 LICENSE 文件。注意：**没有 LICENSE ≠ 保留灵活状态**，而是默认"保留所有权利"，
  外部用户没有明确的复制/修改/分发许可——这会直接阻碍开源贡献与采用。
- 依赖链：build123d（MIT）、cadquery-ocp（LGPL，随包分发 .so/.dll 合法）、FastAPI/React（各自宽松）。
  内核与主仓均为自研代码，重许可的法定障碍不存在（单一版权方）。

## 决定（方案 A：AGPL 社区版 + 商业双许可）

1. **主仓采用 AGPL-3.0-or-later**（见 `LICENSE`），与内核一致：
   - `-or-later` 为未来升级留口；
   - AGPL 堵住"云厂商闭源托管 Varen 服务"这条最常见的搭便车路径；
   - 桌面个人用户与学术用户不受实质约束（AGPL 义务只在分发/网络服务对外提供时触发，且仅约束衍生作品的源码提供）。
2. **官方保留商业许可通道**：OEM、闭源分发、企业内嵌集成购买商业许可。
   因团队持有全部版权，双许可在法律上无障碍。
3. **贡献者条款**：CONTRIBUTING.md 要求 DCO 签署 + 明示授权（贡献内容按 AGPL 授予，且授予项目维护者
   再许可权 relicensing grant），保证未来改许可或双许可卖断时不需回头征求每个贡献者。

## 为什么不选其他方案

- **方案 B（核心 MIT 化 + 云端闭源）**：传播最容易，但装配 agent + 验证门控是当前唯一差异化壁垒，
  以现有声量（1 star）没有网络效应兜底，MIT 化等于把"可审计机械设计 Agent"品类定义权免费让给
  CurrentCAD / Adam / Zoo。留作 Plan B：若 6 个月后开源社区证明贡献吞吐需要更宽许可再切换（`-or-later` 留口）。
- **方案 C（闭源，只发二进制 beta）**：最快开始用户验证，但放弃开源分发与可信度叙事，
  与"证据型宣发"（公开 benchmark、失败周报、审计链）的品类定位自相矛盾。

## 对外表述纪律

可以说："开源（AGPL）+ 商业双许可；本地优先，数据不出你的机器（除你配置的模型端点）。"
不要说："完全免费商用" / "随便闭源用"——这两句都会在未来变成法律与信任双重麻烦。
